# Systems Thinking — Mapping Reference

Depth companion to [`SKILL.md`](../SKILL.md), which owns the procedure and the output format. This file explains why steps 2–5 exist and how each one fails.

**Where this applies:** these tools require standing outside the system and modelling it, which works in Clear and Complicated systems. In a Complex system, cause↔effect exists only in hindsight, so prefer a small experiment over leverage-point analysis. In a Chaotic system none of it applies — stabilize first, analyze later. See [`swadia-typology.md`](./swadia-typology.md).

**Evidentiary limit:** this tradition rests on six short statements from Lenny's Podcast guests, one each ([raw quotes](./lenny-guest-insights.md)). Read them as prompts for the questions worth asking, not as a developed method. The decision rule lives in the type classification, not here.

## Why Each Step Exists

### See the system before optimizing inside it

Seth Godin frames strategic thinking as seeing the system: the invisible rules, culture, and interfaces that decide whether a product or organization works. A change that only makes sense inside one player's view means the system has not been seen yet.

### Players and incentives (step 2)

Sriram Krishnamurthy proposes enumerating every player, what each wants, and how those wants interact, and argues this beats jobs-to-be-done for multi-agent trade-offs: JTBD models one buyer's job, while systems produce outcomes from several actors' incentives at once.

The failure mode: a reward is a proxy for a goal, and people optimize what is measured. The British bounty on dead cobras in Delhi paid for the proxy and produced cobra breeding. Before intervening, ask what the intervention actually pays for.

### Stocks and flows (step 3)

Will Larson models reality as stocks and flows: stocks accumulate, flows move between states. A hiring pipeline is a candidate stock with inflow (sourcing, applications) and outflow (hire, reject, withdraw); a product funnel is a user stock with activation and churn flows.

The failure mode: interventions target the stock ("we need more users") while control lives in the flows ("acquisition rate against churn rate"). A stock that cannot move at the demanded rate will not move, however loudly it is asked.

### Second, third, and fourth-order effects (step 4)

Hari Srinivasan treats managing a complicated ecosystem as a distinct skill from managing a product, because effects cascade past the immediate impact. Nickey Skarstad frames second-order thinking as reasoning beyond today's decision: choices made now set the constraints available later.

The failure mode: the first-order effect is the visible one and usually the only one measured. Effects of order 2+ arrive through other players' reactions, which is exactly why they go unseen.

### Automate recurring pain (step 5)

Melissa Perri and Denise Tilles look for the process someone hated enough to systematize. Recurring manual pain is a reliable signal: repetition proves the need is real, and each repetition raises the cost of the manual path relative to building the system.

## Modelling Stocks and Flows

1. Name the stock in units that accumulate and can be counted: candidates, active users, dollars, tickets in a backlog.
2. List every inflow and outflow that changes that stock, with the rate each one currently runs at.
3. Compare the rate the plan assumes with the rate the flows support. The gap is the constraint, and it is usually a flow.
4. Choose the intervention at the flow, not at the stock.

## Finding Leverage Points

Rank candidate interventions by how much of the system each one moves relative to its cost and reversibility. High-leverage points tend to sit at:

- A shared rule or default that many players already follow — behaviour changes without asking anyone to change.
- A feedback delay — shortening it changes what players optimize for.
- A misaligned proxy reward — correcting it removes the cobra effect.
- An information flow that reaches nobody able to act on it.

Prefer the intervention with the smallest blast radius that still moves the constraint. When two options move it equally, take the reversible one.

## Systematizing Recurring Pain

Systematize when the same manual work keeps recurring and the manual path now costs more than building the system would, the steps are stable enough to encode, and a wrong result is detectable. Build the detection before the action: in most systems the value is in noticing, not in acting.
